## 0. 一句话结论

DSH WebUI 是**单会话、聊天中心、强可观测**的执行面；LoopDesk 要叠上去的是**多 Loop 聚合 + 控制面 + 验证面**。
叠加的本质不是"重写界面"，而是：

> **把 DSH 的三视图会话区变成 LoopDesk 的右栏事件流，把 LoopDesk 的控制/验证面（左导航 + 中目标/Gate）包在它外面，把 DSH 的扁平会话列表升级为多 Loop lane 仪表盘。**

DSH 给的（不要重建）：会话列表、对话视图、轨迹视图、Session log、底部实时数据条、审批弹窗、子代理进度、预设选择器、resume/fork。
LoopDesk 必须加的（才是叠加价值）：多 Loop lane 聚合、信任/验证视觉语言、控制面（Goal/Todo/Manager/Gate/Quota）、类型化 Gate 持久化、配额/防空转。

## 1. DSH 当前 WebUI 骨架（事实基线）

| 区域 | DSH 现状 | 特征 |
| --- | --- | --- |
| 顶栏 | workspace/身份 + 预设选择器（Standard / PTC / Minimal / Creator）+ 新会话 | 会话模式创建时固定，不可中途切换 |
| 左侧栏 | **扁平会话列表**（单栏） | 单会话聚焦，无分组、无聚合 |
| 中间区 | 活动会话 + 三视图 Tab（对话 / 轨迹 / Session log）+ 底部输入框 | 聊天中心；轨迹视图=每 turn/step/工具调用的原始时间线（含 token、耗时） |
| 右侧 | 子代理面板 / inspector（子代理下拉 + 实时进度） | 多 provider 并存，并行进度可见 |
| 底栏 | 实时数据条：tok/sec、缓存命中率、工具调用数、turns、steps | 透明、诚实，但**不含预算/配额** |
| 交互原语 | 风险操作前弹**审批确认** | 阻塞式，无"类型化 Gate + 证据链接 + 待我审批角标" |

DSH 的"轨迹视图"与本仓库需求①天然对齐：它本就呈现 **推理过程 + 执行轨迹**，且是 event-sourced（Session log 为唯一权威，可回放/可恢复）。

## 2. LoopDesk 两页的设计主题（要叠加什么）

### 主题 A — 多 Loop 聚合（来自仪表盘页）
- 按项目 / 运行时分 **lane**；每张 Loop 卡片含状态点、运行时徽标、阶段、进度条、配额/证据/活跃时间。
- **信任条（TrustRow）**：分段条"已验证 N/M"——绿=已验证 / 白=执行中 / 琥珀=待人工 / 红=失败 / 灰=未覆盖。
- 顶部"信任状态图例"：强化产品核心论点"可信状态只来自验证"。

### 主题 B — 控制/验证面（来自单 Loop 三栏工作区）
- 左导航：目标与待办 / 进度与证据 / 验证与检查点 / 配额与预算 / 事件流回放 + 当前区块白色左轨。
- 中栏：目标卡（子目标进度）→ **Manager 下一步面板**（批准/修改）→ 有界子任务列表（状态+证据链接）→ **人工门控 Gate 卡片**（问题+选项+证据+批准/修改/暂停）。
- 右栏：**事件流 · DSH**（推理 / 轨迹 / 工具 / Checkpoint 四类标签）。

### 主题 C — 验证视觉语言（Impeccable pass 的签名视觉，最该叠加）
- 产品灵魂"验证与执行分离"在原 DSH 里**完全不存在**（DSH 没有 Auditor 概念）。
- LoopDesk 必须把它变成一眼可辨的信号：卡片信任条 + 事件流"Executor 自述(灰) vs Auditor 已验证(绿)"的状态机。

### 主题 D — 配额/防空转（来自仪表盘 + 设计系统）
- DSH 底栏有 tok/sec 等透明指标，但**没有预算/配额**。LoopDesk 需并入院配额槽位、待审批 Gate 数、当前 Checkpoint。

### 主题 E — 类型化 Human Gate（来自工作区页）
- DSH 已有审批弹窗（阻塞式）。LoopDesk 把它**类型化 + 持久化**：问题 + 选项 + 证据链接 + 三动作，浮于任意视图，顶栏带"待审批 N"角标。

### 主题 F — DSH 推理/轨迹原生（需求①，已落右栏）
- DSH 的 Trajectory 视图 = LoopDesk 右栏事件流数据源；Session log = 回放权威。无需转换层。

## 3. 叠加映射：每个 LoopDesk 主题落在 DSH 骨架的哪

```
DSH 骨架                          →  LoopDesk 叠加后
─────────────────────────────────────────────────────────────────
顶栏（预设选择器）               →  顶栏保留预设 + 新增：全局配额余额、待审批 Gate 角标、新建 Loop
左侧扁平会话列表                 →  【主题A】多 Loop lane（按项目/运行时分组）+ 每张卡信任条 + live 白色描边
中间三视图会话区（对话/轨迹/log）→  【主题B/F】降级为右栏"事件流·DSH"（推理/轨迹/工具/Checkpoint 标签）+ 中栏让位给控制面
中间区输入框                     →  【主题B】中栏变控制面：目标卡 + Manager 下一步 + 子任务 + Gate（输入=注入指令/审批）
右侧子代理面板                   →  保留并扩展：子代理实时进度 + Auditor 只读核查进度（验证面）
底栏实时数据条                   →  【主题D】并入：配额槽位 + 待审批 Gate + 当前 Checkpoint + 原有 tok/sec 等
审批弹窗（阻塞）                 →  【主题E】类型化 Gate：问题/选项/证据 + 浮层 + 角标，可设硬阻塞或软提醒
```

**关键判断**：DSH 的"中间三视图"不应被丢弃，而是**下沉为右栏事件流**；腾出的中栏才是 LoopDesk 控制面的主场。这既复用 DSH 的推理/轨迹原生能力（需求①），又把"聊天中心"翻转为"控制/验证中心"。

## 4. 颜色与令牌校正（重要）

**决策变更（2026-08-17，用户拍板）**：原稿建议"画布品牌青 → 设计系统 teal `#15B8A6`"。用户最新指示为"**以 DSH 的配色为主，符合它的外观设计**"。经核验 DSH WebUI 实测外观（报道：整体风格从蓝变**黑**、蓝鲸 LOGO 变黑鲸；默认皮肤 = Coding 深色编辑器白字；可换肤但默认中性），DSH 默认是**近黑中性底 + 白字 + 单色 chrome，颜色只留给状态语义**——这与设计系统 teal、也与早期品牌青都不同。

> 注（2026-09-14）：设计系统已定为 **v2.0**，主强调为 emerald `#34D399`；本段提到的 teal `#15B8A6` 属已作废的 v0.1-draft。此为历史决策记录，保留原貌。

**结论：以 DSH 默认中性深色编辑器为视觉基准**。LoopDesk 两页画布已据此重建（同文件 Page 2「LoopDesk × DSH 外观」）。调色板：

| 用途 | 值 | 说明 |
| --- | --- | --- |
| 背景底 `--bg-base` | `#0A0A0B` | 近黑中性（DSH"从蓝变黑"，非蓝调深底） |
| 面板/卡片 `--bg-surface` | `#151517` | |
| 悬浮/徽标/输入 `--bg-elevated` | `#1C1C1F` | |
| 侧栏/凹陷 `--bg-sunken` | `#0D0D0F` | 左栏、右栏、上下文栏 |
| 边框 `--border` | `#262629` | |
| 强调边框 `--border-strong` | `#38383D` | 运行中卡片、激活导航 |
| 文字主 `--text-primary` | `#F2F2F2` | 白字（Coding 皮肤） |
| 文字次 `--text-secondary` | `#A0A0A6` | |
| 文字弱 `--text-muted` | `#6B6B70` | |
| 主操作 / 激活 / live | `#F2F2F2` 填充·黑字 | **白**即 DSH 主色，不引入蓝/青/teal |
| 已验证 `--success` | `#3FB950` | 绿 |
| 待人工 `--warning` | `#E3B341` | 琥珀 |
| 失败 `--danger` | `#F85149` | 红 |
| 运行中/live | `#F2F2F2` | 白（以圆点/描边表达"活跃"） |
| 已暂停/未覆盖 | `#6B6B70` | 灰 |

信任条分段：绿=已验证 / 白=执行中 / 琥珀=待人工 / 红=失败 / 灰=未覆盖。

**与设计系统的冲突处理**：设计系统（`docs/design-system.md` **v2.0**，主强调 emerald `#34D399`）是 LoopDesk 自有 Web UI 的事实源，但本页属"叠加 DSH WebUI"场景，用户明确以 DSH 外观优先。建议后续在 `loopdesk-web-ui` 二开时通过 DSH 的 `--dsw-alias-*` / `--dsw-specific-*` token 覆盖层落地，使 LoopDesk 控件在 DSH 壳内自然继承 DSH 中性主题，而非强行套用 LoopDesk 强调色。

## 5. 集成姿态对齐（避免文档冲突）

- 本叠加思路对应 `dsh-base-integration-proposal.md` 的 **§5.5 / §11 长期二开蓝图**：fork DSH，新增 `@loopdesk/loopdesk-web-ui` 插件"替换/扩展 `dsh-web-app`"。
- 这与 §4.3 / §8 的短期"不复用 dsh-web-app"**不矛盾**：短期是黑盒调用（Phase 1），本思路是 Phase 4 产品面。用户明确"以 DSH WebUI 为基础叠加"，即采用长期姿态。
- 设计时应面向"扩展 DSH Web UI"而非"从零另做一套"，以最大化复用 DSH 的会话/轨迹/Session log/审批/子代理进度。
