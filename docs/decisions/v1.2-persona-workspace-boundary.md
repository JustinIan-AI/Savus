# 产品决策 — LoopDesk v1.2 Persona、Workspace Type 与目录边界

> 状态：已决策
> 版本：v1.2
> 最后更新：2026-07-29
> 负责人：Product / Engineering
> 输入：`docs/plans/prd-v1.2-gap-backlog.md`、`docs/prd/personal-loop-workspace-v1.1.zh.md`、`docs/decisions/runtime-matrix.md`、`docs/features/core-feature-list.md`、`src/loopdesk/loop_workspace/schema.py`、`src/loopdesk/loop_workspace/layout.py`

## 1. 决策背景

v1.2 要关闭原始 PRD 与 v1.1 之间剩余的 P3 边界问题，避免把 personal-first / local-first 的 loop workspace 扩散成通用知识工作平台、多租户协作平台或团队文件平台。

## 2. 决策结论

### 2.1 Persona 边界

- v1.x 主线 persona 继续收敛为 **independent developer / AI 原生开发者**。
- 技术负责人、知识工作者等 persona 仅作为 **skill/template 示例** 保留，不作为独立产品线或独立用户系统进入 v1.2。
- 允许 personal knowledge / writing / research loop 以 skill/template 形式存在，但不做 rich media 优先、不扩成 broad media pipeline。
- 不做独立的 user profile system 来表达 persona；persona 差异通过 `selected_template`、`context`、`skills`、`loop_engine` 表达。

### 2.2 Workspace Type 边界

- `workspace_type` 保留在 `LoopWorkspaceState`，默认继续是 `project`。
- v1.2 只实现 **Project workspace**；`personal` / `business` 先作为 enum 占位，不引入隔离、template、memory 或 billing 差异。
- 未来若扩展，通过 project metadata / template 表达，而不是重建 multi-persona 产品线。

### 2.3 目录边界

- `.loopdesk/` / `LOOP-STATE.json`、`memory/`、`skills/`、`artifacts/`、`worktrees/`、`personal_templates/`、`context/` 保留为 **workspace-level 最小目录契约**。
- 这些目录是用户可以浏览的 durable 接口，同时受 `require_under_workspace` 保护，不能逃出 workspace boundary。
- 允许 `.loopdesk/` 之外存在 project assets；不要求 tool-agnostic 全仓目录标准化，也不强制原始 PRD 的 `tasks/` / `tools/` / `agents/` / `logs/` 全量恢复。
- durable source of truth 继续以 `LOOP-STATE.json` 为主；目录是 state 的伴生文件，不是第二真源。

## 3. 实现锚点

- `src/loopdesk/loop_workspace/schema.py:21` 保留 `WorkspaceType`，但 v1.2 只深度支持 `PROJECT`。
- `src/loopdesk/loop_workspace/layout.py:9` 保留最小目录契约与 context 文件位置。
- `tests/test_loop_workspace/test_v11_context_type.py:11` 覆盖 workspace type、context files、directory snapshot。

## 4. 边界声明

- 不做 team workspace、member management、shared cloud rooms。
- 不做 broad media authoring、voice replies、complex card interactions。
- 不做 separate user profile system 或 persona-driven runtime routing。
- 若后续要支持 second persona 或 second workspace type，先回到本决策补充影响评估，再进 v1.3+。
