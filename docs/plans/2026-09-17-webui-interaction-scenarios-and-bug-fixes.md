# LoopDesk WebUI 交互场景测试计划与 Bug 修复清单

## 1. 核心目标
解决当前任务全生命周期管理中存在的交互断层：
1. 修复新建任务与新建项目弹窗中的按钮可见性问题，确保高亮可点击；
2. 修复新建任务的状态机映射，确保新建任务准确落入第一列「待办（Todo）」并展示流转动作；
3. 打通左侧项目管理真实数据源，创建项目后左栏与顶栏即时联动，点击项目时隔离呈现项目内部会话记录；
4. 跑通看板卡片上的全流程交互动作（开始执行、提交评审、审批放行、驳回返工）。

## 2. 场景化测试计划（Scenario-based Interactive Test Plan）

### 场景 1: 弹窗主按钮样式与操作可见性
- **用例 1.1**：打开「新建任务」弹窗，验证「开始任务」按钮在正常状态下为明亮的翡翠绿背景（`#34D399`）、纯黑文字，并支持点击触发提交。
- **用例 1.2**：点击「+ 新建项目」打开子弹窗，验证「确认创建项目」按钮为明亮翡翠绿背景、高亮可见并可正常提交。
- **用例 1.3**：当选择远端且缺少前置依赖时，「开始任务」按钮变为禁用态（`cursor: not-allowed`），并清晰提示「等待前置服务就绪」。

### 场景 2: 任务创建与列位落位（待办 Todo）
- **用例 2.1**：在弹窗中选择归属项目、模板、填写描述后点击「开始任务」，后端以 `status: planned` 创建新任务。
- **用例 2.2**：验证新建的任务立即出现在第一列「待办」，且卡片右上角呈现「开始执行」快捷操作按钮。
- **用例 2.3**：验证「待办」列头数字联动递增（+1），左侧导航「任务看板」徽标同步递增。

### 场景 3: 项目管理与动态联动
- **用例 3.1**：新建项目成功后，左侧项目列表实时更新出新项目行，并标注正确的模式徽标（Local/Remote）。
- **用例 3.2**：点击左侧项目列表中的任一项目，顶栏项目指示器联动同步切换，看板平滑重拉取该项目专属的任务集合。
- **用例 3.3**：点击左侧「会话」抽屉，抽屉顶部清晰展示当前所属项目，列表仅呈现归属于当前项目的内部会话记录。

### 场景 4: 任务全生命周期卡片事件闭环
- **用例 4.1**：在「待办」卡片上点击「开始执行」，卡片平滑移入第二列「进行中」，状态变为 `active`。
- **用例 4.2**：在「进行中」卡片上点击「提交评审」，卡片平滑移入第三列「评审中」，状态变为 `in_review`。
- **用例 4.3**：在「评审中」卡片上点击「通过」，弹出审批门确认窗，提交后卡片移入第四列「已完成」。
